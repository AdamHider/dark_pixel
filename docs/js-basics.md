## 1. Модули: import и export

Каждый файл в `src/` — отдельный **модуль**. Всё, что модуль отдаёт наружу, помечается `export`;
то, что берёт у других, — `import`.

```js
// src/core/math.js — отдаём наружу две функции
export const clamp = (value, min = 0, max = 1) => Math.max(min, Math.min(max, value));
export const lerp = (a, b, t) => a + (b - a) * t;

// src/render/painter/layers/coast.js — берём clamp себе
import { clamp } from '../../../core/math.js';
```

Нюансы:

- **Путь относительный** и почти всегда с расширением `.js`. `../` — «выйти на папку выше».
- Имя при импорте должно совпадать с именем при экспорте (это «именованный импорт»). Можно
  переименовать: `import { clamp as ограничить } from ...`.
- `export default` в проекте **не используется** — только именованные экспорты. Так видно, что
  именно вы подключаете.
- Импорт не выполняется «внутри» функции: браузер читает все модули заранее. Поэтому **нельзя**
  импортировать то, что зависит от конкретного экземпляра карты.

> Почему это важно. Порядок подключения модулей фиксирован, а экземпляры (`MapGenerator`,
> `MapPainter`) создаются уже потом, в `main.js`. Данные карты передаются не через импорт, а
> аргументами — см. [классы](#5-классы).

## 2. Переменные: const и let

```js
const size = this.map.size;   // значение не переприсваивается
let best = -1;                // будет меняться ниже в цикле
```

- `const` — «ссылка не меняется». Но **содержимое** объекта или массива менять можно:
  `const a = []; a.push(1);` — законно.
- `let` — если переменную нужно переприсвоить.
- `var` в проекте не используется: он «протекает» из блоков и легко приводит к ошибкам.

Правило проекта: по умолчанию `const`, `let` — только когда действительно нужно менять.

## 3. Функции и стрелки

Обычная функция:

```js
export function percentile(values, share) {
    const sorted = Float32Array.from(values).sort();
    return sorted[Math.floor(sorted.length * share)];
}
```

Функция-стрелка (короткая запись):

```js
export const clamp = (value, min = 0, max = 1) => Math.max(min, Math.min(max, value));
```

Разница, которая важна именно здесь:

- У стрелки **нет своего `this`**. Она берёт `this` из окружающего кода. Поэтому стрелку удобно
  передавать как колбэк (`array.filter(i => this.regionId[i] === id)`), где нужен внешний `this`.
- У обычной функции `this` свой — он зависит от того, как её вызвали. Методы слоёв
  (`paintShores() { ... }`) — обычные функции: в них `this` — это сам painter.

Значение по умолчанию (`min = 0`) подставляется, если аргумент не передан или передан `undefined`.

## 4. `this`, методы и главный приём проекта: Object.assign

### Что такое `this`

`this` — «тот объект, у которого сейчас вызван метод». В коде проекта методы лежат в объектах-слоях:

```js
// src/render/painter/layers/coast.js
export const coast = {
    roundCoastCorners() {
        const size = this.map.size;   // this — экземпляр MapPainter, у которого вызвали метод
        ...
    },
};
```

Когда позже вызывается `painter.roundCoastCorners()`, `this` внутри станет `painter`, и
`this.map` найдётся. Это позволяет писать метод один раз, а данные брать из экземпляра.

### Приём проекта: методы «подмешиваются» в прототип

Класс `MapPainter` сам хранит только состояние и порядок слоёв, а сами слои лежат в отдельных
файлах и добавляются к классу одной строкой:

```js
// src/render/painter/map-painter.js
Object.assign(MapPainter.prototype, base, coast, tileColors, hills, shores, /* ... */ vegetation);
```

Что здесь происходит:

- `base`, `coast`, ... — это **объекты с методами** (например, `{ roundCoastCorners() {...} }`).
- `MapPainter.prototype` — «общая часть» всех экземпляров класса: то, что есть у каждого painter.
- `Object.assign(цель, источник1, источник2, ...)` копирует все свойства из источников в цель.

Итог: методы из всех файлов становятся методами класса. Это тот же результат, что если бы вы
написали их прямо в классе, но разложенный по файлам.

> Аналогия. Класс — это шкаф. `Object.assign` — это развесить по нему полки из разных коробок.
> После этого любой экземпляр класса видит все полки.

Практический вывод: **новый слой = новый файл + добавить его имя в `Object.assign` + вызвать
метод из `paint()`**. Большой класс трогать не нужно. То же самое устроено в `MapGenerator`
(`steps/`) и `MapRenderer` (`renderer/`).

## 5. Классы

```js
export class MapGenerator {
    static DEFAULTS = DEFAULTS;         // свойство самого класса, не экземпляра

    constructor(options = {}) {         // вызывается при new MapGenerator(...)
        this.options = { ...MapGenerator.DEFAULTS, ...options };
        this.size = this.options.size;
    }

    get landShare() {                   // «геттер»: читается как поле, без скобок
        return this.landTiles.length / (this.size * this.size);
    }
}

const generator = new MapGenerator({ size: 150 });  // создание экземпляра
generator.generate(1);                               // вызов метода
console.log(generator.landShare);                    // геттер: БЕЗ скобок ()
```

- `constructor` — что выполнить при создании объекта. Здесь настройки сливаются с настройками по
  умолчанию (пользовательские перекрывают стандартные).
- `this.size` — «поле экземпляра»: своё у каждого объекта.
- `static` — принадлежит классу целиком (`MapGenerator.DEFAULTS`), а не конкретной карте.
- `get` — геттер: `generator.landShare` вычисляется на лету, но выглядит как обычное поле.

## 6. Плоские массивы (typed arrays) и почему индексы

Карта — квадрат `size × size`. Вместо «массива массивов» проект хранит всё в **одном плоском
массиве**, а клетку `(x, y)` находит по формуле:

```js
i = y * size + x;         // номер клетки
x = i % size;             // обратно: столбец
y = Math.floor(i / size); // и строка
```

Типы массивов:

| Тип | Что хранит | Пример в проекте |
| --- | --- | --- |
| `Float32Array` | дробные числа | `elevation`, `moisture`, `temperature` |
| `Uint8Array` | целые 0..255 | `terrain`, `biome`, `river` |
| `Int16Array` | целые -32768..32767 | `regionId`, `factionId` (там бывает -1) |
| `Int32Array` | целые ±2 млрд | `pixels` (упакованные цвета) |

Зачем именно они:

- **Быстро и компактно.** Миллионы клеток и пикселей: обычный массив объектов был бы в разы
  тяжелее.
- **Все массивы одной длины**, и один и тот же индекс `i` годится для всех: `terrain[i]`,
  `biome[i]`, `river[i]` — про одну и ту же клетку.

Пример из кода:

```js
// src/map/map-generator.js
this.terrain = new Uint8Array(count);
this.regionId = new Int16Array(count).fill(-1);   // -1 — «клетка вне региона»
```

`.fill(-1)` заполняет весь массив значением `-1` сразу.

> Ловушка. В `Uint8Array` отрицательное число «заворачивается» (станет 255). Если нужны
> отрицательные значения (например, `-1` для «нет региона»), берите `Int16Array`/`Int32Array`.

Пиксели карты — тоже плоский массив, но с индексом `k = gy * width + gx` (ширина в пикселях).
Правило проекта: **`i` — клетка, `k` — пиксель**.

## 7. Битовые операции: цвета, маски, биты

Цвет в проекте — **одно 32-битное число**, а не три числа «r, g, b». Внутри оно разложено по
байтам так: `AA|BB|GG|RR` (альфа, синий, зелёный, красный).

```js
// src/render/color.js
export const packRgb = (r, g, b) => 0xFF000000 | (b << 16) | (g << 8) | r;
```

Разберём операторы:

- `<< n` — сдвиг битов влево (умножение на 2ⁿ): `b << 16` ставит синий в третий байт.
- `|` — побитовое «ИЛИ»: склеивает байты в одно число.
- `0xFF000000` — непрозрачная альфа.
- `& 255` — оставить только младший байт (взять красный из цвета).
- `>>> n` — сдвиг вправо **без знака** (важно для цветов, см. ниже).

Как разобрать цвет обратно:

```js
// src/render/color.js
export function shadeFast(color, amount) {
    const r = color & 255;              // красный — младший байт
    const g = (color >>> 8) & 255;      // зелёный — второй байт
    const b = (color >>> 16) & 255;     // синий — третий байт
    ...
}
```

> Нюанс со знаком. `0xFF000000 | ...` даёт **отрицательное** число (старший бит = 1). Поэтому
> цвета лежат в `Int32Array`, а не `Uint32Array`. И поэтому при чтении используется `>>>`
> (беззнаковый сдвиг): обычный `>>` сохранил бы знак и испортил бы байты.

Биты используют и для дорог: в одной клетке хранится, в какие из 8 сторон идёт дорога.

```js
// src/map/steps/roads.js
this.roadLinks[previous] |= 1 << forward;    // включить бит направления
this.roadLinks[tile] |= 1 << (7 - forward);  // и противоположный ему
```

Проверка бита — через `&`: `if (links & (1 << d)) { ... }`.

## 9. Деструктуризация и spread

### Деструктуризация — «разобрать объект/массив на переменные»

```js
// src/render/painter/layers/coast.js
const [dx, dy] = offset;                 // из массива
const { size, regionId } = this.map;     // из объекта: size = this.map.size, regionId = this.map.regionId
```

### spread `...` — «разложить/собрать»

```js
// слить настройки: стандартные + пользовательские (пользовательские перекрывают)
this.options = { ...DEFAULTS, ...options };

// скопировать массив
const copy = list.slice();       // то же, что [...list]
```

Нюанс, который в проекте решён явно: если пользователь передал `undefined`, spread **затрёт**
значение по умолчанию. Поэтому в `MapPainter` ключи с `undefined` отфильтрованы:

```js
...Object.fromEntries(Object.entries(options).filter(([, value]) => value !== undefined))
```

## 10. Значения «пусто»: undefined, null, опциональные операторы

- `undefined` — «значения нет» (не задано).
- `null` — «значение нарочно пустое».

```js
const region = this.map.getRegionInfo(info.regionId);   // может вернуть null
```

Безопасный доступ:

```js
this.onArmyClick && this.onArmyClick(army);   // вызовем, только если функция задана
```

Современная запись:

- `obj?.field` — взять поле, если `obj` не `null`/`undefined`, иначе `undefined` (не падать).
- `a ?? b` — взять `a`, а если оно `null`/`undefined` — `b`.
- `x ||= value` — присвоить `value`, только если `x` «пустое».

Пример из проекта:

```js
// src/game/game-state.js
return this.relations.get(this.relationKey(a, b)) || 0;   // нет отношения — считаем 0 (нейтралитет)
```

> Ловушка. `||` считает «пустым» и `0`, и `''`. Если ноль — допустимое значение, берите `??`:
> `treasury[f] ?? 0` (а не `|| 0`). В проекте так и сделано:
> `const gold = state.treasury[state.currentFaction] ?? 0;`

## 11. Map и Set

Обычный объект `{}` хранит ключи-строки. `Map` — словарь с ключами любого типа, `Set` — набор
уникальных значений.

```js
// src/game/game-state.js — отношения между фракциями: ключ "0|2" -> число
this.relations = new Map();
this.relations.set(key, value);
const value = this.relations.get(key);   // undefined, если нет

// src/game/game-state.js — зона контроля: набор клеток без повторов
const zone = new Set();
zone.add(tile);
if (zone.has(tile)) { ... }
```

`Map`/`Set` удобны тем, что `.has()` и `.get()` работают быстро, и значения не повторяются.
Обход: `for (const tile of reachable.keys())` или `for (const army of this.armies)`.

## 12. Методы массивов: map, filter, find, some, sort

Короткие «однострочники» вместо циклов:

```js
// filter — оставить подходящие
const tiles = this.landTiles.filter(i => this.regionId[i] === regionId);

// find — первый подходящий (или undefined)
const army = this.armies.find(a => a.id === id);

// some / every — «есть хотя бы один» / «все»
const coastal = this.neighbors(i).some(j => !this.isLand(j));

// map — преобразовать каждый элемент
const names = state.generator.factions.map((faction, f) => `${faction.name}: ...`);

// sort — сортировка (МЕНЯЕТ массив!), возвращает тот же массив
regions.sort((a, b) => b.population - a.population);   // по убыванию населения
```

> Ловушки.
> - `sort()` без аргумента сортирует **как строки**: `[10, 2, 1]` станет `[1, 10, 2]`. Всегда
>   передавайте функцию сравнения `(a, b) => a - b`.
> - `sort`, `reverse`, `push`, `splice` меняют исходный массив. Если нужна копия — сначала
>   `list.slice()`: в проекте так делает `shuffled()`.

## 13. Циклы

Обычный счётный цикл — для сеток и массивов:

```js
for (let y = 0; y < size; y++) {
    for (let x = 0; x < size; x++) { ... }
}
```

`for...of` — «по элементам» (чище, когда индекс не нужен):

```js
for (const army of state.armies) this.actArmy(army, culture);
```

Обратный проход (часто в перемешивании):

```js
for (let i = copy.length - 1; i > 0; i--) { ... }
```

> Нюанс производительности. В самых горячих местах (пиксели) проект пишет обычные `for` со
> счётчиком: они предсказуемее и быстрее, чем `forEach`. В остальном коде читаемость важнее.

## 14. Числа: Math, округление, imul, hypot

```js
Math.floor(v)     // вниз: 2.9 -> 2;  -2.1 -> -3
Math.round(v)     // к ближайшему: 2.5 -> 3
Math.min(a, b)    // меньшее
Math.max(a, b)    // большее
Math.abs(v)       // модуль
Math.sqrt(v)      // корень
Math.hypot(dx, dy) // длина вектора (корень из dx²+dy²), без переполнения
Math.imul(a, b)   // умножение 32-битных целых БЕЗ потери точности (для хешей)
```

`Math.imul` нужен именно для хешей: обычное `a * b` для больших чисел теряет точность
(числа в JS — дробные двойной точности).

Индекс клетки по строке/столбцу и обратно:

```js
const i = y * size + x;
const x = i % size;
const y = Math.floor(i / size);   // НЕ i / size — получится дробное
```

## 15. Замыкания и bind

**Замыкание** — функция «запоминает» переменные из места, где её создали:

```js
// src/render/painter/layers/scene.js
case Resource.WOOD: this.collectTrees(items, x, y, i); break;
...
items.push({ y: y * T, draw: () => this.drawWheat(x, y) });   // x, y запомнены в стрелке
```

Функция `draw` будет вызвана позже, но всё ещё «видит» свои `x`, `y` и `this`. Так строятся
списки отложенных отрисовок (`this.emissive` — источники света рисуются после цветокоррекции).

`bind` жёстко привязывает `this`:

```js
// (пример приёма) — метод, который передадут как колбэк и вызовут без объекта
const handler = this.draw.bind(this);
```

Стрелка `() => this.draw()` — современная альтернатива `bind`: `this` берётся из окружения.

## 16. Канвас: ImageData и пиксели

Карта рисуется не готовыми спрайтами, а **пиксель за пикселем** в один `ImageData`.

```js
// src/render/painter/map-painter.js
const image = this.ctx.createImageData(this.width, this.width);
this.pixels = new Int32Array(image.data.buffer);   // смотрим на те же байты, но как на целые числа
...
this.ctx.putImageData(image, 0, 0);                // отправить картинку на холст
```

- `ImageData.data` — обычный массив байтов RGBA. Мы «накладываем» на него `Int32Array`, чтобы
  писать **целый цвет одним присваиванием**: `pixels[k] = color`.
- `k = y * width + x` — индекс пикселя (не путать с индексом клетки `i`).
- `drawImage(src, sx, sy, sw, sh, dx, dy, dw, dh)` — скопировать кусок холста (так работает
  камера и мини-превью в панели дипломатии).

> Нюанс. Порядок байтов в `Int32Array` зависит от машины, но `packRgb` собирает цвет так же, как
> его читает `ImageData` на подавляющем большинстве платформ (little-endian). Поэтому формула
> `AA|BB|GG|RR` работает.

## 17. «Случайность», которая не меняется: хеши

Обычный `Math.random()` при каждой перерисовке дал бы новый узор, и карта «кипела» бы. Поэтому
случайные числа выводят из координат **хешем** — одинаковый вход всегда даёт одинаковый выход.

```js
// src/render/painter/noise.js
export function tileHash(x, y, k) {
    let h = (Math.imul(x, 374761393) + Math.imul(y, 668265263) + Math.imul(k, 1274126177)) | 0;
    h = Math.imul(h ^ (h >>> 13), 1103515245);
    h ^= h >>> 16;
    ...
    return h >>> 0;   // беззнаковое 32-битное
}

export const hashUnit = (x, y, k) => tileHash(x, y, k) / 4294967296;   // то же, но 0..1
```

`k` — «соль»: разные соли дают разные, но стабильные узоры (тени, трава, камни...). Так детали
не меняются при зуме и перерисовке.

Для генерации карты (её нужно уметь воспроизвести по сиду) есть `createRandom(seed)` — обычный
генератор, но с фиксированной последовательностью для данного сида.

## 18. Мелкие ловушки

- **`Math.floor(i / size)`, а не `i / size`.** Деление даёт дробь; строку получают округлением.
- **`Uint8Array` не хранит отрицательные.** Для `-1` берите `Int16Array`.
- **`sort` меняет исходный массив.** Нужна копия — `list.slice()`.
- **`||` и `??` различны.** `0` и `''` — «пусты» для `||`, но не для `??`.
- **У стрелки нет своего `this`.** Для методов объекта — обычная функция.
- **`this` теряется при передаче метода как колбэка.** Используйте стрелку или `.bind(this)`.
- **`==` сравнивает с приведением типов** (`'1' == 1` — истина). В проекте везде `===`/`!==`.
- **Массивы сравниваются по ссылке.** `[1] === [1]` — ложь; кэш в проекте сравнивает **ссылку** на
  исходный массив, а не содержимое.
- **Индексы: `i` — клетка, `k` — пиксель, `x`/`y` — клетка, `gx`/`gy` — пиксель.** Путаница здесь
  — самая частая ошибка в этом коде.
